01 · The big ideacore

One agent isn't enough — so I run a fleet that feels like one.

Key transfer: from "chat with a website" to "delegate to a capable assistant."
  • Open the frame: "This is about turning an open-source AI assistant into something that runs my household — not a product I pay for."
  • Set the bar low: "You don't need ML expertise to follow — just curiosity about how a tool becomes a teammate."
  • Name the four things that matter: model-agnostic, persistent memory, real tools, learns skills.
  • End with the mindset shift — pause, let it land.
Four pillars: model-agnostic · persistent memory · real tools · learns skills
02 · Architecturedemo

Six layers, all on one machine.

The mental model you'd hand anyone inheriting the system.
  • Walk top-down quickly — Surfaces → Orchestration → Memory → Retrieval → Action → Governance.
  • Click one or two layers live so they see it's not a static diagram.
  • Emphasize the bottom: "All six layers, on one PC. Not a cloud data center."
  • Humor line: "The whole architecture fits on this laptop — the 'server room' is a desk."
6 layers deployed on a single Windows box · 20 active agent profiles across them
03 · Surfacesdemo

Four ways to talk to the same agent.

Same brain, same memory, same tools — different door.
  • Lead with what maps to their life: "Desktop for deep work, Telegram when you're out, terminal for heavy lifting."
  • Hit the tab switch live — it's the one interaction that reads instantly as "real."
  • Surprise hook: "Telegram isn't just chat — it has the same full tools as everything else."
  • Keep the dashboard brief — it's admin; don't let it eat time.
Desktop · Terminal · Telegram · Web dashboard — one core, four doors
04 · Profilescore

A fleet of focused agents, not one generalist.

"The people of the system" — each with identity, skills, models, permissions.
  • Make it human: a personal assistant, a business agent, per-person agents, and specialists each owning one job.
  • Land the principle: least privilege — no agent gets more access than its job.
  • Reassure on safety: "A specialist having a bad day can't take down the whole house."
20 active profiles · per-person + business + specialist councils (health, product-imagery)
05 · Memorycore

It remembers me — without a database to babysit.

Memory is what separates a tool from an assistant.
  • Distill to three: who you are, lessons learned, searchable history.
  • "A skill is memory too" — procedures get packaged and reused, not relearned.
  • Story with a principle: I ran a dedicated memory server, then replaced it with built-in native memory because simplicity wins. Say it plainly.
Persistent profile + readable notes + searchable session history. No extra service to keep alive.
06 · Retrieval & the second braindemo

Two searches, one brain.

Everything I know lives as plain-text notes; two engines reach it.
  • Fast local search = "where is that file" in milliseconds.
  • Semantic retrieval = ask by meaning, get relevant notes even when the words differ.
  • Type in the filter live ("semantic") so they see search narrow the cards.
  • Payoff: notes are portable plain text — no lock-in, easy to back up and share.
Markdown = source of truth · search stays on the machine, OneDrive-safe
07 · Automationkeep short

It runs on its own schedule.

The underrated feature: it acts on timers and boards, not just when asked.
  • Scheduled tasks: weekly digests, reports, reminders — like a smarter cron.
  • Kanban boards: ongoing work organized into boards, routed to the right agent.
  • One strong line: "Automation is where it stops being a toy."
23 boards · scheduled jobs · static sites deploy to free hosting with one command
08 · Modelsdemo

Routing by value, not by default.

The flag feature: it picks the right brain per task based on what the task is worth.
  • Plain phrasing: cheap brain for routine work, stronger brain for hard problems, local-only for private.
  • Flip the toggle live so they see "cost-aware routing ON/OFF."
  • Why it matters: expensive brains only when it's worth it — quality and cost in one lever.
Everyday floor + a build/code model + escalation tier + a fully local model for private topics
09 · Privacy & securitycore · slow down

The part that makes the rest safe to use.

This is the trust section — give it weight, don't rush it.
  • Lead with the boundary: medical, finances, family-private, secrets — never leave the machine. Non-negotiable, not a preference.
  • Local-first by default: a local model handles private topics; nothing sent anywhere.
  • Reassure on mechanics: secrets live in encrypted stores pulled on demand; external text is data, not orders.
  • Trust tiers: Inform → Suggest → Execute — it earns authority gradually.
Trust tiers · allowlisted brains · encrypted secret stores · external text = data not orders
10 · How to begindemo

Your first ten minutes, step by step.

The path you'd put in front of anyone starting fresh.
  • Walk the 8 steps fast — install → configure → chat → tell it who you are → try a tool → add a skill → schedule one thing → then scale.
  • Run the terminal demo live (Replay); it's the "wow" moment — let it finish naturally.
  • Honest advice to close: don't configure everything upfront — start real and small, add complexity when a task calls for it.
8 steps · 10 minutes · live typing demo + replay/step controls
