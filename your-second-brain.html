Your brain leaks. So I built a second one — and then taught it to think.

This session answers the two questions that came up most after the first talk: what does "second brain" actually mean, and how is a semantic, knowledge-graph brain like the one I run any different? We'll go from plain notes, to a real brain, to the tools that make it reason over itself.

01 · The idea

A second brain is an external memory you can actually query.

The human brain is great at having ideas and terrible at remembering where it put them. A second brain is the fix: a disciplined store of your own knowledge — notes, decisions, research, and the connections between them — that an assistant can retrieve instead of you re-reading everything.

🧠

Why your head isn't enough

Working memory is tiny, and recalling is unreliable. You don't need a better memory — you need a place where retrieval is someone else's job.

🗂️

It's a capture discipline, not a tool

The tools matter far less than the habit: capture ideas the moment they land, then organize them so they're findable later.

🔎

Retrieval over storage

Most people over-collect and under-retrieve. A second brain is worthwhile only if it makes yesterday's thinking cheap to find today.

🔗

Connections are the value

Raw notes are a pile. The moment you link related ideas, the pile becomes a network you can traverse — which is exactly where the modern tools step in.

02 · How it's built

The anatomy of a second brain.

Whatever tool you choose, every strong second brain shares the same skeleton. This is the mental model — and it's the same one my house system is built on.

1
Capture
Inbox — dump everything, unprocessed
2
Organize
File into projects, areas, resources, archives
3
Distill
Compress notes into the idea that matters
4
Link
Connect related notes into a network
5
Retrieve
Query it — by keyword, by meaning, by connection
This is the CODE loop (Capture · Organize · Distill · Express) with one addition — Linking — because that's what unlocks the AI tools we're about to meet.
03 · Methods worth stealing

Nobody invented this — they systematized it.

A second brain isn't one recipe. Here are the three frameworks the modern tools are built on, each with a different philosophy. Tap each to see the idea behind it.

📌

Projects

Active efforts with an end — a launch, a deck, a build. Finite, time-bound, and current.

📚

Areas

Standards you maintain with no finish line — health, home, relationships, work discipline.

🗄️

Resources

Reference material you may want later — research, topics, interests, bookmarks.

📦

Archives

Inactive items no longer relevant, kept for history and retrieval without cluttering the active view.

Why PARA wins: it's action-oriented — organized by what you're doing now, not by topic. When you finish a project, it demotes to archive automatically. Clean, intuitive, and it's the base layer of many of the tools we'll see.
🧩

One idea per note

Atomic notes. Each captures a single thought in your own words, never a wall of copied text.

➡️

Link, don't file

Notes connect to other notes. The value is the web of references you build, not the folder you filed them in.

🌱

Grow organically

New ideas attach to existing ones. The network compounds the more you feed it, until it starts suggesting connections you'd missed.

🏷️

Indexed by emergence

There's no strict taxonomy. Structure emerges from the links — which is why it maps so well onto graph databases.

Why it matters here: Zettelkasten's "link, don't file" is literally what a knowledge-graph brain automates. The human discipline became the machine's default.
📄

Markdown is the source of truth

Files on disk you can open in any editor. No proprietary store, no lock-in.

🗺️

Three layers

Immutable raw sources → curated wiki pages → a schema that defines the conventions agents must follow.

🔗

Compile once, reuse forever

Instead of re-deriving every answer from scratch, the wiki compiles knowledge once and keeps it current, cross-referenced.

🤖

Agent-in-the-loop

The human curates sources; the agent summarizes, files, cross-references, and flags contradictions. That's exactly how a second brain becomes self-maintaining.

Where this sits: Karpathy's LLM Wiki showed that if the notes are plain markdown, the AI can both read and write them — turning a passive store into an active, compounding knowledge base.
04 · The AI layer

And then an agent gets to read it.

The pieces so far are pure notes. The modern step is adding a layer that can search, summarize, and connect them automatically. This is what people mean by a "semantic brain" — and it sits on top of a regular second brain, never instead of it.

💬

Keyword search

The classic. Fast, exact, but blind to meaning — "gut inflammation" won't match "colitis."

🧠

Semantic search (vectors)

Embeds each note as a vector of meaning. "gut inflammation" will match "colitis" because they live near each other in meaning-space.

🕸️

Graph retrieval

Notes become entities with relationships. "Who works at X?" isn't a text search — it's following a typed edge from X to the person.

⚖️

Hybrid fusion

The best systems combine all of these and fuse the results — keyword precision + semantic recall + graph structure — ranked together.

05 · GBrain

GBrain: a self-wiring knowledge graph.

GBrain is the semantic brain I run locally. It's Garry Tan's open-source system, and it's the best current example of turning a second brain into something that reasons about itself.

🕸️

Self-assembling graph

Every note it ingests gets scanned for entities and relationships — people, companies, events — wired into a typed knowledge graph with zero LLM calls for extraction.

🧠

Hybrid retrieval

Combines keyword (tsvector), vector (pgvector), and graph links, fuses them and ranks with an LLM. That's the "semantic brain" in action.

⚖️

Proven, not promised

It publishes retrieval benchmarks — 49.1% precision@5 / 97.9% recall@5 — and beats its own graph-disabled version by 31 points. Measured, not marketed.

🛡️

Runs on your machine

Embedded Postgres (pglite) + a local embedding model. Your notes never leave your hardware. For private life-admin, that boundary is the point.

🧠 How GBrain actually works

Three layers: (1) your plain markdown stays the single source of truth; (2) GBrain reads it into an embedded Postgres index with vector embeddings + a knowledge graph of entities and typed edges; (3) a "dream" cycle runs on a schedule to enrich and consolidate. When you ask a question, it fuses keyword + semantic + graph results and ranks them. You still edit the notes in any editor — the graph is derived, so nothing is locked away.

06 · Open Brain (OB1)

Open Brain: one memory, every AI tool.

A different philosophy from the same family. Open Brain (OB1) is built around the idea that every AI you use — Claude, ChatGPT, Cursor, coding agents — should share one memory of you, through one open protocol.

🔌

Cross-tool by design

It's a database + vector search + an MCP protocol, so any AI can plug in. One brain, all of them reading and writing the same store.

📥

Import your digital life

20+ recipes pull in ChatGPT, Google Takeout, Obsidian, X, Instagram, Perplexity — parsers, dedup, embeddings, ingestion all included.

🧩

Extension learning path

Progressive builds — household knowledge, maintenance, family calendar, meal planning, CRM, job pipeline — that compound into a household brain.

👥

Active community

Almost-daily merged contributions (700+ commits, 886 forks). It genuinely does update more often than GBrain — there are simply more hands on it.

⚖️ The honest comparison — what OB1 is, what it isn't

OB1 is broader (cross-tool, imports, extensions) and hotter (community cadence). But it's a different category from GBrain: it's memory infrastructure, and its design center is a managed cloud database (Supabase) that your memory syncs into. GBrain is deeper and local: a self-wiring knowledge graph with published retrieval benchmarks that runs entirely on your own hardware. There is no published benchmark showing OB1 does better semantic search — its edge is breadth, not measured retrieval accuracy.

The takeaway: these aren't competitors — they're answers to different questions. GBrain answers "how do I make my own brain reason over itself, privately?" OB1 answers "how do all my AIs share one memory?" For my private, local-first household brain, GBrain wins on the one axis that matters: it never ships my life to a cloud store.
07 · Second brain vs semantic brain

So: what's actually different?

Flip the switch to see the difference land. A second brain and a semantic brain are not two options — they're two layers, and you want both.

Semantic layer ON — GBrain/Open Brain on top
🗂️

Second brain (the base)

Your organized notes. Projects, areas, resources, archives. Human-curated, plain text, portable. This is what you can build in an afternoon with a folder and a habit.

🧠

Semantic brain (the layer)

An index on top that adds meaning and structure: vector embeddings, a knowledge graph, and fused retrieval. This is what makes your notes findable by meaning, not just by word.

📌 One-line version

A second brain is the bookshelf. A semantic brain is the librarian who actually understands what's on it. You don't choose one — you build the bookshelf, then let the librarian sharpen it. Mine are separate layers precisely so the notes stay portable while the intelligence on top gets to be sophisticated and local.

08 · Build yours

Your path, start to finish.

This is the process I'd hand you — and it's exactly what the companion skill automates during a fresh Hermes Desktop setup.

1

Pick your notes home

A folder on disk, synced if you want portability. Plain markdown — you're not renting a database yet.

2

Lay down PARA + an inbox

Projects / Areas / Resources / Archives, with a capture inbox at the top. This is your filing discipline.

3

Write the schema

One file defining how notes are named, tagged, and get frontmatter — so an agent can file and retrieve consistently.

4

Add an index + a log

An index lists every note; a log records what changed and when. These two pages are what keep it from rotting.

5

Start capturing

Drop everything into the inbox. Twice a week, distill to the idea and file it. Capture beats collection.

6

Link as you go

Every new note connects to at least two existing ones. This is what later makes the graph brain possible.

7

Optional: add the AI layer

Point a semantic brain (GBrain-style) at your notes so retrieval becomes meaning-aware. Only worth it once you have a corpus worth retrieving.

8

Let an agent maintain it

Give your assistant the skill that files, summarizes, cross-references, and flags contradictions — your brain starts running itself.
