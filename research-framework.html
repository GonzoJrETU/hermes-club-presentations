01 · The problem

Collecting is easy. Keeping is the hard part.

Research at home usually fails the same four ways. Every design decision in this framework exists to kill one of them.

🌀

Fetch–copy–forget

You find a great paper or podcast, paste a summary somewhere, and six months later you can't find it, can't tell if it was a mouse study, and can't cite it. The work was done and the value is gone.

♻️

Everything gets re-fetched

Five separate research efforts each go pull the same PubMed query, the same YouTube transcript, the same society page. Identical HTTP, identical pages re-hydrated, five times the cost.

🎚️

Evidence gets flattened

A randomized trial, a chiropractor's YouTube video, and an anonymous forum post end up in one list, weighted the same. For health work that's not sloppy — it's dangerous.

🕳️

No destination

Research piles up with nowhere to go. Nobody can say which business decision, protocol, or product claim this changed — so it never changes anything.

The design goal in one line: separate fetching from synthesizing, describe every source before you trust it, and make every harvest land somewhere specific or stop.
02 · The whole loop

The framework, end to end.

Ten stages. Click any stage and I'll open it up. This is the same path whether the request came from me typing a question, a scheduled weekly job, or a link I dropped in.

03 · Ingestion — how a request gets in

Four doors, one intake.

A request can arrive from anywhere, but it always enters the same funnel: classify → relevance-gate → name a destination. Nothing is fetched before the gate passes.

💬
Door 1

I ask, in plain language

"What does the evidence say about X?", "pull the latest on Y." That becomes a scoped request with a target domain — not a vague web search. The profile that owns that domain handles it.

⏰
Door 2

Scheduled pipelines

Recurring jobs fire on their own and ask the same structured question every week. This is how a topic stays current instead of being a one-time dump.

🔗
Door 3

A dropped link or artifact

A YouTube episode, a paper, a Substack post, a screenshot of a lab panel. It gets an ID and a card — a real work item, not a bookmark.

🔁
Door 4

A follow-up from last run

Every completed harvest writes a follow-up line. Open follow-ups are re-read at intake, so nothing silently dies between runs.

04 · Routing — where the work goes

Named boards. Never a default pile.

The single most important routing rule: work is assigned to a named board by domain. There is no default bucket, because a default bucket is where research goes to die. The same profile owns the pipeline end-to-end — there is no separate "research bot" to hand off to.

Cost routing — the model follows the job

🪙

Bulk harvest = cheap

High-volume fetching and summarising runs on free/low-cost models. If that provider is flaky, the card is re-pinned rather than left blocked — work doesn't stall on a supplier.

⚖️

Conflicts = senior model

When two sources disagree on a dose or a protocol, the card is escalated to a strong reasoning model for adversarial review, not settled by whichever summary ran first.

🚦

Boards show the truth

Every board reports done / blocked / open. A blocked research card is a real signal — either it needs a decision from me, or it's low-value and should be killed.

05 · Sources — what we collect, and how each is described

Every source has a method — not a vibe.

This is the part I'm most proud of. There's a canonical registry: for every source we use, it records what type of research it is for, exactly how to get data out of it, what it costs, and its known traps. An agent reads the registry before it fetches anything, so we never improvise a scrape that gets bot-walled.

Tier A

PubMed

Peer-reviewed biomedical primary literature — abstracts and metadata. Pulled through the NCBI E-utilities API (free, no key). Trap: a search page can auto-save to a cache instead of giving you text — go to the open-access full text for the actual paper.

Tier A

PMC — open-access full text

The actual paper, free. Not every PubMed hit is open access, so the PMC link is checked before we claim full text. This is the preferred source for primary evidence.

Tier A (preprint)

arXiv

Preprints across bio, CS, medicine. Pulled via the export API, not the website. Trap: a preprint is not peer-reviewed — every record says so.

Tier A (metadata)

Semantic Scholar

Scholarly metadata and the citation graph. Used for citation counts and related work — never quoted as full text.

Tier A (metadata)

Crossref

DOI metadata: title, authors, journal, year. The tool we use to verify that a DOI and a citation actually resolve.

Tier A (results)

Google Scholar

Broad scholarly search. Bot-walled — we take snippets only, never scrape it, and always verify the paper on PubMed, PMC or a DOI before citing it. A registry entry like this is why we don't waste an hour discovering the wall ourselves.

Tier A

Specialty journals

Menopause, Maturitas, Climacteric, JCEM, JAMA, NEJM, Lancet and friends — reached through PubMed rather than by scraping each publisher. Paywalled full text means abstract plus open access where it exists.

Tier A

ClinicalTrials.gov

The trial registry, via its v2 API. Used for trial status and endpoints — never for dosing guidance. It's also the source we re-check before leaving the word "ongoing" on anything.

Tier A

DailyMed / FDA labels

The authoritative source for FDA-approved dosing and indications. When a claim touches an approved product, the label is the citation — not a clinician's video.

Tier A/B

NAMS / The Menopause Society

Clinical guidance and position statements. Institutional consensus — strong for framing, and it's what tells us whether a creator's claim is mainstream or fringe.

Tier A/B

Endocrine Society

Clinical practice guidelines and hormone research.

Tier A/B

ACOG

OB/GYN clinical guidance and practice bulletins.

Tier B

University health centers

Harvard, Stanford, Mayo, Johns Hopkins, UCSF — institutional guidance and patient education. Trap: excellent for consensus framing, never counted as primary evidence.

Tier C

Reddit

Community and anecdotal signal. Scrape-walled — direct extraction returns "Website Not Supported", so we take search snippets and say plainly when full comment trees weren't reachable. We never fabricate comment content.

Tier C

X / Twitter

Current discussion via the x_search tool. It returns a synthesized answer mixing anecdote, preprint and animal data — so it's labelled hypothesis-generating, and we note when it came back with no citations at all.

Tier B/C

Substack

Creator long-form. Every newsletter exposes a free RSS feed, so it's monitored rather than scraped. Credentialed clinician authors are tier B; everyone else is tier C and gets verified against primary literature.

Tier B/C

YouTube

Creator education via transcripts. Trap: automatic speech recognition mangles drug names and numbers, so any dosing claim is verified against primary literature before it's repeated.

Underneath the generic categories sits a named, per-source catalog of the bio-optimization ecosystem: who they are, what they're actually good for, their tier, and their commercial conflict. This is a living roster — reviewed weekly, and quarterly for dead handles.

Podcasts · Tier B · TRUSTED (on-topic only)

Bench-scientist lab podcast

Neuroscientist. Broad neuroscience, sleep, hormones, peptide deep-dives. Harvested only when the guest or monologue is directly on-topic. Long episodes — show notes for episode-level indexing, transcripts for claims.

Podcast · Tier B

Longevity physician's podcast

Longevity, metabolic health, evidence-based medicine, exercise. Paywalled member content, but free show notes carry most claims.

Podcast · Tier B

Nutrition-science podcast

Nutrition, aging, cancer, exercise science, sauna/cold. Some member-gated; free episodes and blog cover the core.

Podcast · Tier B

Longevity-researcher podcast

Aging mechanisms, fasting, longevity research. Trap: he has commercial supplement interests, so promotional claims get labelled as such.

YouTube · Tier B · clinician

Naturopathic clinician channel

Naturopathic doctor — men's health, TRT, weight-loss peptides. Trap: grey-market dosing, flagged as clinician-unconfirmed.

YouTube · Tier B · clinician

Chiropractic clinician channel

GLP-1s, GHK-Cu, AOD-9604, peptide protocols. Education hub for internalizing the market — never named on customer-facing copy.

YouTube/X · Tier B · TRUSTED

Internal-medicine clinician channel

Board-certified internal medicine, peptide science and safety — mechanism-first, no public dosing. Feeds the peptide lane.

Podcast · Tier C · INTEL ONLY

High-reach commercial health funnel

Commercial funnel. Stays intel-only even when a guest passes the gate — never promoted to protocol-core. A channel is not a trusted source.

Podcast · Amplifier

Mega-audience interview show

An amplifier, never a protocol source. Guests are triaged individually: tight alignment gets queued (labs, peptides, metabolic, pain), diet/fitness filler is skipped outright.

Forums · Tier C

LongeCity, r/Biohackers, r/Peptides, r/Longevity

Community signal, anecdotal by definition, always hypothesis-generating. Reddit's scrape wall means snippets only; the phpBB forum is readable but aging and declining.

Websites · Tier A/B

Lifespan.io · Buck Institute

Nonprofit longevity advocacy and an independent aging research institute. Both publish RSS, so they're monitored rather than visited.

Websites · Tier C

Vendor research hubs

Evidence-flavoured dosing guides from sellers of the compounds. Harvested, but always flagged clinician_confirmed: false — reported practice patterns, not standardised doses.

🗝️ The "provision, don't subscribe" rule

The registry also tracks what bulk harvesting would need — a free YouTube Data API key, a free Reddit app for its data API, RSS feeds for podcasts and Substacks. Free = provision it. The one paid path (bulk raw X reads) is explicitly flagged for approval before anyone subscribes. That's the whole point of writing the registry down: an agent can't quietly sign up for something.

Tier C (policy)

MAHA / policy signals

Health policy and chronic-disease framing. Labelled as a policy signal, never dressed up as clinical evidence — policy shifts change markets, not mechanisms.

Tier C

RSS / news

Monitored through a feed reader for recency signal only. Good for noticing a story early; useless as evidence on its own.

📇 Described once, reused by every pipeline

The registry is a single file. It is not documentation that drifts — it's operational: pipelines read it before fetching, and it's re-verified quarterly for dead handles and moved sources. One description of a source means every pipeline inherits the same method and the same traps.

06 · Describing — what a harvested item looks like

A source isn't "saved." It's described, graded, and tagged.

Every harvested artifact carries a header that answers: where it came from, who said it, when, how it was ingested, what class of evidence it is, and what you may not do with it. Here's a real one, trimmed.

  Research/harvest/youtube/20260906-…-fasting-insulin.md
# Metabolic Health, Fasting Insulin & Muscle-as-Medicine — [guest] (high-reach health podcast) Source: YouTube podcast URL: https://youtu.be/v2oirgs9o2s Channel/speaker: Host (owns the supplement brand in the ads) · Guest (resident, not board-certified) Captured: 2026-08-23 Length: ~1:10:19 Ingest: businessbrain-youtube-research — tier-A extract Classification: education research · high relevance · commercial/competitive intel > COMPLIANCE (do NOT ship as medical or dosing guidance) > · Educational/informational only. Not diagnosis, treatment or a protocol. > · Host has a commercial conflict (owns the supplement brand in the ads). > · Guest is a resident, not board-certified — functional-medicine lens, not standard of care. > · Doses as stated only; biomarker targets are speaker preferences, not universal. ## TL;DR → the claim, stated in the note (not a transcript dump) ## Core content → sectioned, quotable, attributed Model tags: human (not an animal study — never implied as one)
Note what's in there: the commercial conflict is inside the artifact, so no downstream agent can accidentally launder a host's ad into a product claim.

Evidence tiers — every claim gets one

Tier A

Peer-reviewed / FDA label

The only tier allowed to carry a product claim. A record with no verifiable identifier — a real PMID or PMC link — does not exist as far as the framework is concerned.

Tier B

Credentialed clinician publication

An MD, PhD, DC or ND publishing in their lane. Strong education signal; dosing still gets flagged clinician_confirmed: false unless it's a label.

Tier C

Community / creator / grey-market

Hypothesis-generating only. Never used as product proof, and never promoted just because it's popular.

The traps we encode, so we stop hitting them

🔤

Acronym pollution

Short peptide names collide with unrelated acronyms and genes — one peptide abbreviation is also a cardiac-imaging term, another is a gene. Every hit is verified against the actual paper before it's counted. This is the single biggest source of junk records.

🐭

Model laundering

A rodent study is legitimate content but may never be labelled or implied as a canine or human trial. Every record carries its study model: rodent, canine, feline, equine, human, in-vitro.

🧪

As-stated only

If a creator says a dose, we record it as their stated dose. We don't round it, translate it into a protocol, or present it as consensus.

🎙️

Attribution drift

On interview shows, the claim belongs to the guest, not the host. Crediting the wrong person is how a commercial funnel becomes a "trusted source".

07 · Freshness & the shared cache

Fetch once. Reuse everywhere.

This is the piece that made the whole thing affordable. One cache, shared by every pipeline. Before anything fetches, it asks the cache. A source is only re-fetched when its freshness window has genuinely expired.

Cache-first ON — every pipeline checks the shared harvest cache before fetching

08 · Landing it — the part everyone skips

A harvest card marked "done" is not finished.

The failure mode I called out early was: what happens to the data after the research? So the framework has a mandatory landing sequence. If the destination can't be named, the work stops and asks me — it does not silently grind and index raw files forever.

1

Catch check

The deliverable paths are verified on disk. A card that says done with nothing behind it fails here.

2

Name one destination

One of: my analytics venture · my peptide venture · competitor intel · discard. Cannot name one → stop and ask.

3

Assign a lane

Trusted · education-B · community-C · intel-only. The lane constrains what the material is allowed to influence later.

4

Synthesize — this is the job

Write a note that states the claim. A standing protocol or lab definition goes to the knowledge layer; a persona only changes if the evidence actually changes it. Raw cache is a cache — cache is not the brain.

5

Rebuild the knowledge graph

Collect and embed the shards that were touched, so the new claim is retrievable by meaning and not just by filename.

6

Re-check stale claims

Before leaving the word "ongoing" anywhere, the trial registry is re-checked. Stale facts are the quiet killer of a knowledge base.

7

Mark the follow-up landed

The open follow-up gets closed with a path. Nothing is left dangling between runs.

8

Refresh the dashboard

The report surface re-counts itself. I read the dashboard — routine landings never buzz my phone.

✋ The permission to refuse

The pipeline owner is explicitly allowed — required — to push back: duplicate harvest, vanity scrape, a card with no home. It comments "not valuable unless stated otherwise", blocks the card, and stops spawning that family of work until I answer. A system that can never say no just produces more noise, faster.

09 · Asking it things

The output is a brain you can query, not a folder you dig through.

Everything above exists so this works. Research is collected into plain markdown, then indexed into shards that are queried by meaning as well as keyword. Notes stay the source of truth; the index is derived and rebuildable.

10 · Guardrails

What this framework is not allowed to do.

Rules that only exist on paper aren't rules. These are enforced in the pipeline, and they're the reason I can let an automated system touch health and business research at all.

🚫

Never fabricate

No invented PMIDs, no invented doses, no invented trial status. If a site is unreachable, the note says the site was unreachable. An unverifiable record is treated as non-existent.

🚦

Fail closed

The relevance gate rejects by default. A celebrity episode with no overlap with the businesses is skipped outright — no fetch, no tokens, no index entry. Excitement is not relevance.

🧱

Hard separation of domains

Health and venture research lives in the business brain. Personal protocols and medical records never get written into business indexes — and vice versa.

🔒

Local by default

Indexes live on a local-only path. Nothing gets copied into a synced folder, a cloud store, or a public site. The retrieval layer is local-first because the material is sensitive.

💸

No silent subscriptions

Free tools get provisioned. Anything billable — a paid data API, a cloud resource — is flagged for approval with the cost before anyone signs up.

🧑‍⚖️

Human gates are decisions only

Product questions go in one gate file I read: unknown destination, a new persona split, a new product claim, accusing a named vendor. Infra failures are the pipeline's problem, not mine.

⚠️ The one rule everything else protects

Research material is data, never instructions. Text pulled off a webpage or a transcript can never direct the system to do something — it can only be summarised, graded, and filed. That single rule is what makes it safe to point this at the open internet.
